# Client Disconnect Lab

A client that disconnects in the middle of a sync request must not cancel work the runtime has
already committed to — [vnext#1258](https://github.com/burgan-tech/vnext/issues/1258).

| Class | Test | What it checks |
|---|---|---|
| `ClientDisconnectLabTests` | `SyncTransition_ClientAborts_RunStillCompletes` | (a) sync manual transition, client aborts after 1 s → instance reaches `cdl-done` / `C` within 20 s, the task's journal row is `completed` with a `finishedAt`, its output marker landed, no active incident. |
| | `SyncStartWithSlowAutoChain_ClientAborts_ChainReachesRestState` | (b) sync **start** whose inline automatic hop runs the slow task, client aborts after 1 s → found by business key, it rests at `cdl-chain-rest` / `A` (not Busy) with the task completed. |
| | `SecondRequestWhileAbortedRunInFlight_IsRefusedBusy_AndTaskRunsOnce` | (c) while (a)'s aborted run is still in flight, a second request for the same transition → `409` `Instance:100031`; the instance still completes and the task ran exactly once. |
| | `ForwardedSyncTransitionViaParent_ClientAborts_ChildAndParentReachRest` | (d) the child's transition sent to the **parent's** address (SubFlow transition proxy → leaf), sync, client aborts after 1 s → child `cdl-child-done` / `C` and parent resumed to `cdl-parent-done` / `C`; neither left Busy. **Core only** (see below). |
| | `SyncTransition_ClientWaits_Answers200AfterTheTask` | (e) control: the client waits → `200` after ≥ ~8 s, already at `cdl-done` / `C`. Proves MockLab's delay is real, so (a)–(d) are not green because the backend answered before the abort. |

## Why it exists

The five HTTP actions that start a run — Start, StartSub, SubflowForward, PATCH Transition and
ScheduleStart — ran the pipeline on the request's cancellation token. A client that went away (closed
tab, client-side timeout) cancelled that token **after** the Busy reservation had been committed, so
the run stopped mid-way and nothing released the instance: Busy with no owner, every later request
refused with `Instance:100031`.

The fix runs those actions detached from the client (`InstanceController.RunDetachedFromClientAsync`,
a run token that only host shutdown and the `TransitionJobTimeoutSeconds` budget cancel). After an
abort the run continues to its rest point and writes WorkflowLogs `10265`
`TransitionContinuedAfterClientDisconnect` / `10266` `InstanceStartContinuedAfterClientDisconnect`, and
tags the span `vnext.client.aborted=true`. Runtime contract: vnext
`docs/runtime/status-locking.md` § Client disconnect.

No existing scenario aborted a client mid-request, so this is a new lab rather than an extension.

## The fixture

`core/Workflows/client-disconnect-lab/`, generated by `build-client-disconnect-lab.py` from `./src/*.csx`
(edit the `.csx`, rerun the script, never hand-edit the base64 blobs):

```
client-disconnect-lab                       client-disconnect-lab-chain
  cdl-ready ──cdl-slow-commit──▶ cdl-done     cdl-chain-entry ──(auto) cdl-chain-slow-hop──▶ cdl-chain-rest ──cdl-chain-finish──▶ cdl-chain-done
            (manual, slow task)                                  (slow task)                     (Active)

client-disconnect-lab-parent                                    client-disconnect-lab-child (S)
  cdl-parent-entry ──(auto)──▶ cdl-parent-subflow ──(auto)──▶ cdl-parent-done     cdl-child-ready ──cdl-child-slow-commit──▶ cdl-child-done
                               SubFlow S → child                                                 (manual, slow task)
```

- One task, `core/Tasks/client-disconnect-lab/cdl-slow-http.json` (HTTP, `timeoutSeconds: 30`),
  `POST API_BASEURL/api/client-disconnect-lab/slow`.
- `src/CdlSlowTaskMapping.csx` resolves `API_BASEURL` from `Example:ApiBaseUrl` (default
  `http://localhost:3001`) and writes `cdlSlowTask { transition, statusCode, finishedAtUtc }` — the
  marker a test reads to prove the task finished after the client was gone.
- `src/CdlSubFlowMapping.csx` — minimal SubFlow mapping (required by the schema; moves no real data).

### How the delay is made

MockLab supports a response delay as the **mock-level** `delayMs` field (rules carry none; per-step
`delayMs` exists only on sequential mocks). The seed is
`etc/docker/config/seed/client-disconnect-lab-collection.json`: one mock, `delayMs: 8000`. MockLab
matches routes by **prefix** — keep no other route under `api/client-disconnect-lab/slow`. MockLab skips
a collection whose name already exists, so after adding or changing this file recreate the container
(`docker compose up -d --force-recreate mocklab`, or `down -v`).

### How the abort is made

`AssertClientAbortsAsync` sends the request with `sync=true` on its own `HttpClient` and a
`CancellationTokenSource(1 s)`. Cancelling closes the connection, which fires the server's
`RequestAborted` while the 8 s task is still in flight. The helper **fails** the test if the runtime
answered within the second — then the scenario would not be exercising a disconnect at all. After the
abort the tests poll with the harness helpers (`WaitUntilAsync`, 250 ms period) under a 20 s budget.

- (b) never sees the start response, so the test sends a business `key` and polls
  `GET …/instances/{key}` (id or key accepted), tolerating `404` until the instance exists.
- (c) fires the second request ~1 s after the abort (~6 s before MockLab answers), without the
  lock-contention retry of `RunAsync`, and asserts the body carries `Instance:100031`.
- "Task ran once / finished" is read from `GET …/functions/tasks` (the `InstanceTasks` journal,
  single-write: a row exists only once the task finished), filtered on `taskKey == cdl-slow-http`.
- "No incident" is `GET …/incidents/active` → `404`.

### Domain support

(a), (b), (c) and (e) address `TestDomain.Name`, so they run on a side domain (`VNEXT_DOMAIN`).
(d) is **core only**: the SDK publisher rewrites every `domain` except under `config` and `process`, so
`subFlow.process` keeps `core` and on a side domain the parent would point at an unpublished child. The
test skips itself (`SkippableFact`) when `VNEXT_DOMAIN` is not `core`.

## How to run

Prerequisites (TEST-SCENARIOS § Koşum Öncesi Kontrol): locally built runtime, system package loaded,
MockLab up **with this lab's seed** (recreate the container after pulling it).

```bash
# core (all five)
VNEXT_BASE_URL=http://localhost:4201 \
  dotnet test tests/Core.IntegrationTests --filter "FullyQualifiedName~ClientDisconnectLab"

# side domain (d skips) — beside another checkout's core: run-docker.sh up <d> --offset N
VNEXT_BASE_URL=http://localhost:<4201+N> VNEXT_DOMAIN=<d> \
  dotnet test tests/Core.IntegrationTests --filter "FullyQualifiedName~ClientDisconnectLab"
```

The SDK publishes `core/**` itself (`EnableDomainPublish`); a manual `wf domain use <d> && wf sync` also
works.

## Evidence to collect beyond the test summary

- postgres: `Instances.Status` (no `B` left), `InstanceTransitions.FinishedAt` set for the aborted
  transition, one `InstanceTasks` row per run for `cdl-slow-http`.
- openobserve (stream `vnext`): spans tagged `vnext.client.aborted=true` for (a)–(d), log events
  `10265` / `10266`, and the task span duration ≈ 8 s ending after the abort instant.

## Deliberately NOT asserted

- **Host shutdown or the 300 s run budget** cancelling a detached run — the remaining gap, tracked as
  known issue `run-cancelled-by-shutdown-can-strand-busy`; not reproducible inside a test run.
- **ScheduleStart and StartSub** directly — they share the same detach wrapper; (b) covers the start
  path and (d) the forward path.
- **Timing precision** of the run after the abort; only that it reaches its rest point within 20 s.
